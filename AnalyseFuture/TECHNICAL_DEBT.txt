Inventory date: 17 November 2026
Scope: active Django/PostgreSQL application and its development/operating model

READ THIS FIRST
This is an evidence-based backlog, not a statement that every listed item is a
confirmed defect or an instruction to activate production. Preserve the existing
implementation. AnalyseFuture upstream snapshots are reference material and must
not become active dependencies merely because their code is available.

Classification:
  DEBT = a maintainability/reproducibility constraint in the current foundation.
  GAP = required capability or operating evidence still missing before release.
  RESEARCH = a question requiring measurement/contract review before a change.
  DEFECT = a reproducible violation; record revision, command and actual behavior.

No new runtime checks were executed to author this file. Prior cloud onboarding
reported 174 application tests on PostgreSQL, 17 backup guards and an isolated
synthetic restore, with local startup/HTTP checks. Those results are useful prior
evidence, not fresh verification of this audit revision or real provider behavior.
No unexplained, newly reproduced application failure is claimed here. The current
audit/validation records should record new failures separately if they occur.

Priority:
  P0 = blocks public live-money launch or trustworthy incident containment.
  P1 = needed for sustainable service, scale or a specific feature's release.
  P2 = measure and prioritize once the core service is reliable.
Owners below are required roles, not claims that named people are assigned.
The dated resolutions below qualify the original cards. External release gates
